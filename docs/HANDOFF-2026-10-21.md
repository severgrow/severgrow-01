## ⚠ (historical) The coastline risk as it stood before the check

`coast-pan-fit` is the Territory work: **pan on both axes, a 44 px cell, one FIT toggle, and a
regenerated coastline** for the shared map. It is committed as `58dd5b4` (pan + FIT) and `34ca8b7`
(coastline) and is **saved on the remote as the branch `coast-pan-fit`** — and, unavoidably, those
same commits are the current tip of `futa0.5-online` because of the 12:42 push.

**Why that was supposed to be held back:** the coastline changes the server cell table
(`server/src/world.ts`) and **the owner reports 9 real player claims on the current shape**. The new
table is **not a superset**: it has **274 cells** instead of 275, **removes 20 ids** and adds 19.
Every claimed cell must exist in the new table or that player's claim is orphaned (the row survives
in `world_claims`, but `worldCell(id)` returns `null`, so the tile renders nowhere and cannot be
defended).

These are the **20 ids that exist at `6a7f1f0` and are gone at `34ca8b7`**:

```
-10,4  -10,5  -10,6  -10,7  -9,4   -9,5   -9,6   -1,-9  -1,-8  -2,-8
0,-8   0,-9   1,-9    2,-10  2,5    2,6    3,4    3,5    4,4    5,4
```

**The gate, in this order:**

1. Ask the database which claims sit on those ids (Supabase → SQL editor):

   ```sql
   select cell_id, owner_id, claimed_at
   from world_claims
   where cell_id in ('-10,4','-10,5','-10,6','-10,7','-9,4','-9,5','-9,6',
                     '-1,-9','-1,-8','-2,-8','0,-8','0,-9','1,-9','2,-10',
                     '2,5','2,6','3,4','3,5','4,4','5,4');
   ```

   **Zero rows** → no orphan risk, the map can stay as it is. **Any row** → that claim is
   orphaned: migrate those ids to the nearest surviving neighbour (a `world_claims` update), or
   revert the map forward before telling the owner it is fixed.

2. Check the 9 real claims in total, not only the 20 ids — the owner's count is the target:

   ```sql
   select cell_id, owner_id, claimed_at from world_claims order by claimed_at;
   ```

   Every id returned must be in the new table. There is no script for this yet; the SQL is the
   check.

3. Only after both pass, rebuild and redeploy the Edge Function so the server bundle carries the
   same table (see *Commands*). The committed bundle is a deploy-time artifact and the last rebuild
   is on branch `edge-deploy` (`11a9262`), not deployed.
